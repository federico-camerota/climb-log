# Mock-up · spreadsheet tabs as they would look (v3)

Files (open in LibreOffice/Excel, or upload to Google Drive and "Open with Google Sheets"):
- `mockup-climbing-journal.xlsx`: **Wellbeing** tab (the mock-up) + an abridged **Session**
  tab it looks up + `_settings` + `_meta`.
- `mockup-finger-strength.xlsx`: **Sessions**, **Hang sets**, **Curl sets** + `_settings` + `_meta`.

These files were generated by a throwaway script that follows `04-storage.md`. They are a
design artefact, not the app. **All data in them is fictional** (the repo is public, D-034);
notes are marked `[ESEMPIO]`, and venues/partners are invented.

**Changes after review**: more readable key row (D-029); finger sets in two tabs (D-030);
finger sessions identified by date + type, so hangs and curls on the same day are rated
separately (D-032); cross-tab lookups use a hidden numeric key column (D-031).

## Layout rules shown
| Element | What you see |
|---|---|
| Row 1 | Human label, bold, centred, coloured by group: **blue** = key (date, session #, set #), **green** = before, **amber** = after, **grey** = AUTOMATIC (formulas), light grey = system columns the app fills. Finger set tabs: blue = hang fields, lilac = curl fields, yellow = common fields |
| Row 2 | Field key in **9 pt monospace, dark grey, on a pale tint of the group colour**, centred, with a **thick line underneath** separating headers from data. The app matches on these keys, so labels can be reworded and columns reordered. A cell note on A2 says not to edit this row. |
| Freeze | Rows 1–2 and columns A–B stay visible while scrolling |
| Dropdowns | 1–10 scales, choices (grip, arms, completed), date validation, number ranges (sleep 0–14 h, edge 5–40 mm, …) with an error message on invalid input |
| Colours | Scale cells red→green (reversed for ↓ columns; effort/RPE neutral, uncoloured); statuses LOW red / WATCH amber / GOOD green |
| Formula rows | Rows 3–202 already contain the AUTOMATIC formulas, so a row you type gets its status at once. Empty rows show nothing. |
| Hidden key column | `key (auto, hidden)` = date × 10 + session # (blank = 1). Used by the cross-tab checks; hidden so you never see or type it |
| Text | Note columns are text-formatted, so Italian notes with accents and apostrophes stay exactly as typed |

Row 5 shows hand entry *before* climbing: only the green part is filled, the pre status
appears at once, the score waits for the post values, and the session check reminds you to
add the Session row.

```
Pre status        =IF($A3="","",IF(COUNT(D3:F3)<3,"",IF(MIN(D3:F3)<=low_max,"LOW",IF(MIN(D3:F3)<=watch_max,"WATCH","GOOD"))))
Post status       =IF($A3="","",IF(COUNT(H3:J3)<3,"",IF(MIN((11-H3),I3,J3)<=low_max,"LOW",IF(MIN((11-H3),I3,J3)<=watch_max,"WATCH","GOOD"))))

Wellbeing score   =IF(COUNT(D3:F3,H3:J3)<6,"",ROUND(AVERAGE(D3,E3,F3,(11-H3),I3,J3),1))
Session check     =IF($A3="","",IF(COUNTIFS(Session!$L$3:$L$202,Q3)=0,"⚠ no Session row","ok"))
key (hidden)      =IF($A3="","",$A3*10+IF($B3="",1,$B3))
```

Hand entry: on a set tab you type the date and the set values. Set # can stay blank. There's
no session type to pick (the tab says it), no session #, and no ids.

Hidden key (D-031): `date × 10 + type code` (1 = Max hangs, 2 = Finger curls). On Sessions it
is computed from the type column; on each set tab the code is fixed by the tab.
```
Sessions · Sets          =IF(OR($A3="",B3=""),"",IF(B3="Max hangs",COUNTIFS('Hang sets'!$N$3:$N$202,P3),COUNTIFS('Curl sets'!$P$3:$P$202,P3)))
Sessions · key (hidden)  =IF(OR($A3="",B3=""),"",$A3*10+IF(B3="Max hangs",1,2))
Hang · key (hidden)      =IF($A3="","",$A3*10+1)
Hang · Set # (auto)      =IF($A3="","",IF(B3<>"",B3,COUNTIFS($N$3:N3,N3)))
Hang · Session check     =IF($A3="","",IF(COUNTIFS('Sessions'!$P$3:$P$202,N3)=0,"⚠ no Max hangs session row","ok"))
Curl · Est. 1RM left     =IF(COUNT(C3,D3)<2,"",ROUND(C3*(1+D3/30),1))
```

## Verification done
- All files recalculated in LibreOffice 26.2 (headless) and every AUTOMATIC value read back;
  the values in the tables above are those results. They match the values computed
  independently in Python from the rules in `00-current-state.md`. (Before the data was
  anonymised, the same formulas were also checked against real rows of the original
  `Climbing_Journal.xlsx` and matched its cached values exactly; that check is not
  reproducible from the public repo and will be replaced by the synthetic parity fixtures of M1.)
  All 200 empty buffer rows show nothing.
- Header rendering checked visually (LibreOffice render).
- Rules found for the formula compiler (in `03-module-framework.md` §2.2b):
  1. `.xlsx` needs the `_xlfn.` prefix for newer functions (`MAXIFS`), or they show `#NAME?`;
  2. computed columns need explicit number formats (a date difference otherwise shows as a date);
  3. composite keys use a hidden numeric key column (date × 10 + session #). Text keys built with
     `TEXT(date,"yyyy-mm-dd")` would break in an Italian-locale sheet (`aaaa`), and
     `SUMPRODUCT` tricks are harder to read and maintain.
- **Google Sheets: checked by you on 2026-10-20.** Both files were uploaded to Drive and opened
  with Google Sheets, and work well there.
