# 06 · UI

Responsive SPA, desktop-first: logging and review happen in the app on the computer; the
phone logs in Google Sheets away from home (D-069). Left sidebar (Today · Log · Records ·
Dashboards · Explore · More), still usable on a narrow window. Light/dark theme.

The sidebar has a burger in the header: on a wide window it hides the sidebar, giving the page
the full width, and the choice is remembered across reloads; on a narrow window the sidebar
covers the page and a link closes it (D-074).

Routes (D-073): `/` Today · `/log/{module}/{form}` · `/records/{module}/{entity}` ·
`/dashboards/{module}` · `/settings`; the module (and entity) is picked at the top of the page
and kept in the URL, so a reload or a bookmark returns to the same view. Data is refetched when
the window regains focus, so entries typed on the phone show up when coming back to the app.

## Pages

### Today (home)
- Done (D-080, #74): `/?date=…` (today by default); the recommendation card per module (headline,
  message, reasons) from `GET /api/recommendation`, and per module the forms due on the day from
  `GET /api/today`: with nothing logged, its entry forms (pre-session or rest day, "one of
  these"); with records, each record's forms (pre, then post), done / partial / missing with the
  sections still to fill (text and `optional: true` fields may stay blank in a done form) and the record's own log check, each linking to its form. Last
  session and days since. Next-morning items and the program snapshot come with their modules.
- Done (D-102): the recommendation's reasons include the weakest area of the latest session
  ("Physical · 3.3", the legacy Summary – Recent); a module with a `training_load` widget shows
  this week's load (Monday to the day): the load, sessions, those without load, the
  acute:chronic ratio with its zone, and the other modules' loads (finger training), as the
  dashboard's load card counts them.
- **Recommendation card**: headline, suggested content, reasons (see `05-analytics.md` §4).
- **Due list** for the selected date (defaults to today) built from all active modules:
  - before climbing: Journal pre-session (wellbeing / physical / mental pre), Shoulder primer done?
  - after climbing: Journal post-session + feel + reflect, Fear falls of today + 20Q,
    Shoulder check-in and exercise log
  - next morning: Shoulder "pain next morning" for yesterday
  - rest day: Journal rest-day form
  Each item shows done / partial / missing (the "log check").
- Snapshot: last session, days since, this week's load, program week and phase for each program,
  and this week's training plan (the planned sessions, today's first; M5, D-103).

### Log (forms)
- Done (D-077, #72): `/log/{module}/{form}?date=…&session_no=…` (a picker for the form, the
  date, dd/mm/yyyy, and the other key parts); the form's sections in YAML order, plus fields of
  other sections whose own `phase` is the form's (the session's duration and notes in the post
  form). The first save creates the record, later ones send only what changed with the values
  as read (a 409 when the sheet changed since: "reload, your changes are kept"). The browser
  checks required fields and numbers; the API is the authority and names the field at fault.
  After saving, the record's statuses and log check.
- Done (D-101, #124): a form with child rows (finger-strength sets) shows, once its choice key
  part is picked (the session type), the child entity whose `parent.fixed` matches it: hang sets
  for Max hangs, curl sets for Finger curls. The day's sets are listed by number, each editable
  or removable (Remove / Keep); "+ hang set" adds a row copying the previous set's
  `copy_previous` fields (protocol and load), a blank new row is ignored. Save writes the
  session first, then the sets in order (removed, changed with the values as read, new without
  a number: the next one, D-050), then reads the session again (its set count changed). The
  sets come between the session's "before" groups (details, wellbeing, soreness) and its
  "after" group (wellbeing, effort, notes).
- Done (D-102): when the workbook can't be reached, the form says so before you type
  ("Offline · read-only", when the snapshot was read) and Save is off, as Records and Today.
- Done (D-100, #122): a field with `visible_if` shows only while its condition holds for what is
  typed so far (the backend evaluates it, debounced; a hidden field isn't checked or saved); a
  text field with `suggest_from_history` (venue, partners) suggests the values typed before,
  newest first.
- Generated from module forms. Large touch targets; 1–10 scales as compact dropdowns that
  start blank, best value first and marked "best", each value with its colour hint (reversed
  for ↓; neutral scales from the lowest, no best) (D-078); text notes with autosave drafts (local storage, never the
  source of truth).
- Pre and post can be filled at different times on the same record (the record is
  created at pre, completed at post).
- Shared fields are prefilled from other modules (e.g. grade, activity).
- **Language**: UI in English. Note fields set `lang="it"` and `spellcheck`, so phone
  keyboards and browser spellcheck use Italian (a configurable "notes language" setting: M6).
  Dates are shown as dd/mm/yyyy, weeks start on Monday, and decimal commas are accepted in number inputs.
- Finger strength: the session form has a "+ set" list; each new set copies the previous
  set's protocol and load so only what changed is edited; fields switch with the session type.
- Fear fall entry: rapid repeated entry ("+ another fall" keeps the rung/level), with the
  advancement assistant result shown after saving.

### Records
Per entity: a filterable, sortable table (all fields + derived), full-text search, click to
edit, soft delete, CSV export. Data issues are highlighted inline.
- Done (D-081, #75): newest first, sortable by any column; by default the key, scores,
  statuses and log check, with a column picker grouped by section and remembered per entity
  (a label shared by several fields gets its section: "Mood (before)", "Wellbeing note
  (after)"); search without case or accents over every text, choice, grade and date field
  (every word must match), with a "Matched in" column naming the hidden fields that matched;
  the table scrolls within one screen, so its scrollbars and header stay in view; data issues marked in
  their cell and listed in a panel (orphan rows too), a switch for the records with issues;
  CSV export of the table as shown (semicolons, dd/mm/yyyy, decimal commas, UTF-8 with BOM).
- Done (D-102): the legacy Log Search's filters: a date range (From / To, both included),
  weekdays, and a status (a class or any class, and a value: LOW finds the records with a LOW
  status); the search reads the derived values too (statuses, log check), and the words found
  are highlighted in the cells searched (accents and case ignored, in the original text). No
  40-row cap; the CSV export takes what is shown.
- Done (D-082, #76): a click (or Enter) on a record opens it in a drawer: the whole record in
  one form (every section, pre and post), its data issues under their fields (a bad value typed
  in a text-like field shown as typed, to be corrected), saved through the write API, and
  **Delete…** (soft delete, after a confirmation). The issues panel offers **Delete row** for
  a row that is no record (no key, a duplicate key, an orphan) and **Create the session** for an
  orphan section row. Read-only while offline.

  when they come. Charts: ECharts behind `components/Chart.tsx`, light/dark, no animation.
- Done, part 2 (D-084, #78): the training calendar (from the first record's month, at most the
  last 12; a square per day on a grid with month lines, coloured by its sessions' worst status,
  rest days in lighter colours by their own status, a letter for the kind of day: G gym, O

- Done (D-098): click a day of the calendar to open its records in a drawer on the right:

bands (as the dashboard's scores line); labels that repeat are told apart by section, entity
or module; "Each record" needs metrics of one entity (by day otherwise). The box-by and
heatmap chart types are in the backlog.
