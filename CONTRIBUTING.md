# Contributing

climb-log is a personal project: the owner decides what goes in and merges every change.
The full workflow is in [`design/08-workflow.md`](design/08-workflow.md); the short version:

- **Discuss first.** Open an issue (feature or bug form) before a pull request. Design changes
  are recorded in [`design/decisions.md`](design/decisions.md).
- **One small PR per task**, on a branch `feat/…`, `fix/…`, `docs/…`, `test/…` or `chore/…`,
  with the sections of the pull request template filled in.
- **Conventional Commits**: `feat: …`, `fix: …`, `docs: …`; imperative subject of at most
  72 characters, and a body that explains why.
- **Checks**: `make install` sets up the pre-commit hooks; `make lint` and `make test` must pass,
  and CI runs them on every pull request. The formula parity tests need LibreOffice: they run
  when `soffice` works (or `CLIMBLOG_SOFFICE="snap run libreoffice"` with
  `CLIMBLOG_SOFFICE_TMP=build/lo-parity` for a snap) and are skipped otherwise, CI included.
  Run them before a pull request that changes formulas, expressions or schema sync.
- **API types**: the frontend's types of the API (`frontend/src/api/schema.ts`) are generated
  from the backend's OpenAPI schema. After changing an API model, run `make api-types` and
  commit the file; `make lint` fails while it is out of date (D-073).
- **Storage tests**: what every backend must do goes in the contract tests
  (`tests/test_backend_*.py`, which use a backend only through `Repository` and the harness in
  `tests/backends.py`); what is particular to one backend (file formats, locks, styles) goes
  next to it (`test_xlsx*.py`, `test_sync.py`, `test_gsheets.py`). The Google backend runs on an
  in-memory Google (`tests/fake_sheets.py`); `CLIMBLOG_GOOGLE_LIVE=1` also runs it on the real
  API with your `climblog google login`, on throwaway sheets named `climblog-test-…` that end in
  your Drive trash. Never in CI; run it before a pull request that changes what is asked of
  Google. `tests/test_gsheets_parity.py` is the formula parity check on Google: run it with
  `CLIMBLOG_GOOGLE_LIVE=1` when a change touches formulas, expressions or sync, like the
  LibreOffice one.
- **Docs**: if behaviour changes, update the design docs, `design/decisions.md` and the
  *Unreleased* section of [`CHANGELOG.md`](CHANGELOG.md) in the same PR.
- **Data**: fictional data only, generated by scripts in the repo. Never commit real journals,
  notes, backups, tokens or `.env` files.
- **License**: contributions are GPL-3.0-or-later. New source files start with
  `SPDX-License-Identifier: GPL-3.0-or-later`, and new dependencies must be GPLv3-compatible.
