# CLAUDE.md

Guidance for Claude Code in this repository. Full rationale: `design/08-workflow.md`.

## Project
**climb-log**: a local web app (FastAPI + React/TypeScript) for logging and analysing climbing
training. The data lives in spreadsheets (Google Sheets or local `.xlsx`) defined by
config-driven module YAMLs. Status and plan: `design/README.md`, `design/07-roadmap.md`.

## Before doing anything
1. Read `design/README.md`, `design/decisions.md` and the roadmap item / issue being worked on.
2. Work in **plan mode** first: propose scope, files, approach and tests; wait for approval.
3. If the design docs don't cover something, or you want to deviate from them, ask. Never decide silently.

## Rules (non-negotiable)
- The owner decides and merges. **Never merge, never push to `main`, never force-push.**
- **Ask before every commit and every push.** Ask before adding dependencies or touching files outside the repo.
- One small PR per task, on a branch `feat/…`, `fix/…`, `docs/…`, `test/…`, `chore/…`.
- **Conventional Commits** (`feat: …`, `fix: …`, `docs: …`), imperative subject ≤ 72 chars, body explains why.
- PR description sections: *What & why* (link D-xxx) · *How to try it* · *Look closely at* ·
  *Alternatives considered* · *Docs updated*.
- **No Claude attribution**: no `Co-Authored-By: Claude` trailer in commits, no
  "Generated with Claude Code" line in PR descriptions.
- If behaviour changes, update the design docs, `design/decisions.md` and `CHANGELOG.md` (*Unreleased*) in the same PR.
- Say how something was verified ("ran pytest: 42 passed", "recalculated in LibreOffice"). Don't claim checks that weren't run.

## Data protection (public repo)
- **Never commit or print personal data**: real journals, notes, backups, snapshots, OAuth
  secrets/tokens, `.env`, `~/.config/climblog/`.
- Tests, fixtures and mock-ups use **fictional data only**, generated by scripts in the repo.
  Never copy real spreadsheets into `tests/` or `design/`.
- Develop against copies or fictional workbooks, never the live Google Sheets unless the task says so.
- Never log note contents.

## Conventions
- Code, comments, docs and UI text in **English**. User notes may be in Italian: keep UTF-8,
  write text cells raw (see `design/04-storage.md` §3b).
- Python 3.12, typed (`mypy --strict`), ruff for format + lint, pytest.
- TypeScript strict, eslint + prettier, vitest.
- Derived values and rules are defined once in module YAML (`design/03-module-framework.md`);
  the Python engine and the generated sheet formulas must agree (parity tests).

## Commands
Python commands run through `uv run` (keeps `.venv` in sync with `uv.lock`); frontend commands
through `pnpm --dir frontend`. Node 22 via fnm (`.node-version`). `make help` lists targets.
- `make install`: install Python and frontend dependencies from the lock files, and the git hooks
- `make dev`: backend (:8000, reload) + Vite (:5173, hot reload); open `http://127.0.0.1:5173`
- `make build`: build the SPA into `backend/climblog/static/`
- `make test`: pytest with coverage + vitest; the formula parity tests run only with a working
  LibreOffice (`CLIMBLOG_SOFFICE`, `CLIMBLOG_SOFFICE_TMP`: see CONTRIBUTING.md); CI skips them,
  so run them locally when a change touches formulas, expressions or sync, and say so in the PR
- `make lint`: ruff, mypy `--strict`, `tsc`, eslint, prettier check (changes nothing)
- `make fixtures`: write the fictional journal workbooks (legacy and new layout) to `tests/fixtures/`
- `make fmt`: apply ruff, prettier and eslint auto-fixes
- `uv run pre-commit run --all-files`: run the commit hooks (data check, lint) on every file
- `uv run climblog module validate FILE...`: check module YAML files (`module schema` prints the JSON Schema)
- `uv run climblog serve [--port 8000] [--reload]`: run the built app on `http://127.0.0.1:8000`
- `uv run climblog import-legacy --journal FILE [--dry-run]`: import the legacy journal, with a parity report (owner runs it on the real file, never Claude)
- `uv run climblog check [MODULE...] [--config FILE] [--apply]`: compare workbooks with their module YAML; `--apply` runs the additive schema sync
- `uv run climblog module create FILE --google` / `module move MODULE --to-google`: make a module's Google Sheet / copy a local module into one and check the copy (the owner moves the real journals, never Claude)
